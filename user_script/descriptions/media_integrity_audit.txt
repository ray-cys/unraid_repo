Purpose: Find unreadable media containers and repeatable video/audio decoder errors before playback, using FFmpeg, FFprobe and Python already present in Bazarr. No additional installation, Docker image/startup/configuration change or media modification.

Schedule: Custom 30 9 * * 3. Wednesday 09:30 Singapore time, with a maximum two-hour work budget. The initial scan is Wednesday 25 November 2026. Existing backup, maintenance and application schedules remain unchanged.

Scope: /mnt/user/media/movies, /mnt/user/media/series and /mnt/user/media/formula1 through Bazarr's existing /data mount. Regular video containers only, including their selected video and audio streams. Downloads, quarantine bins, private/secure media, symlinks, ISO/IMG and standalone audio/subtitle files are not decoded.

Process: Inventory file identities; front-load new/changed-file container and stream checks for up to 25% of the runtime (30 minutes); then decode successive overlapping media ranges. Save the next range so large files resume across weekly runs. Prefer in-progress files and new/changed work while reserving time for older periodic checks. Successful unchanged files become due again after 180 days. A quick probe, sampled range or old mtime is never treated as full verification.

Limits: One unprivileged worker in Bazarr; two video threads, one audio/filter thread, nice 15, requested idle I/O priority and 2 GiB decoder virtual-address-space limit. Slow ranges shrink after timeout. Scheduling priority is best-effort; this is not a container-wide CPU/RAM limit. Ten-minute settling protects recently changed files. Runtime/checkpoint limits do not guarantee timely interruption of kernel-blocked disk I/O.

Coordination: Defer or stop work when storage/array state is unavailable, Mover/parity I/O/backups are active, Bazarr is under maintenance, or Plex is transcoding. Backup locks are checked briefly; no two-hour lock delays appdata backup. Existing work is checkpointed, never used to claim an interrupted range passed. Container downtime/tool changes leave affected checks unverified.

Findings: Retry a decoder/container error on the same unchanged file when time permits. Distinguish repeatable errors from unsupported decoders, timeouts, permissions, I/O errors, empty/short decode output and changing files. No automatic deletion, quarantine, repair, re-download, Arr command, permission change or Docker restart. Two clean same-range rechecks can close an old finding; replacement files need a completed planned-range cycle. Inventory removal is reported as removed, not repaired.

Notifications: One grouped scan summary with actual counts, named findings, diagnostic excerpts, positions, recovery reasons, deferred work and a partial throughput/backlog estimate. Normal healthy runs remain a weekly summary rather than per-file emails. A failed notification stays pending; unchanged reruns within 24 hours are suppressed after successful delivery. Notification details are byte-limited, with every exact finding/progress record retained in compressed state.

State/logs: /mnt/vault/cloud/logs/script/media_integrity_audit. One compressed state, one previous validated state, latest-report.txt, a notification outbox/receipt, and a 1 MiB active log with two backups retained for up to 30 days. No syslog writes or accumulating per-file reports. Operational-state export includes the queue for recovery. Backup Health Audit checks scheduling, missed completion and failed delivery.

CLI: /bin/bash SCRIPT --help or --version performs no scan. --status reads the saved receipt only. --inventory-only inventories/stats paths and saves state without probing/decoding or sending a normal email; it can wake drives and does not establish media health. No argument starts the real read-only scan. Completed planned-range coverage is not a single uninterrupted full decode, a known-good checksum, subtitle validation or a guarantee of Plex-client playback.
