Purpose: Find unreadable media containers and repeatable video/audio decoder errors before playback, using FFmpeg, FFprobe and Python already present in Bazarr. No additional installation, Docker image/startup/configuration change or media modification.

Schedule: Custom 30 9 * * 3. Wednesday 09:30 Singapore time, with a maximum two-hour work budget. The initial scan is Wednesday 25 November 2026. Existing backup, maintenance and application schedules remain unchanged.

Scope: /mnt/user/media/movies, /mnt/user/media/series and /mnt/user/media/formula1 through Bazarr's existing /data mount. Regular video containers only, including their selected video and audio streams. Downloads, quarantine bins, private/secure media, symlinks, ISO/IMG and standalone audio/subtitle files are not decoded.

Process: Inventory file identities; front-load new/changed-file container and stream checks for up to 25% of the runtime (30 minutes); then decode successive overlapping media ranges. Save the next range so large files resume across weekly runs. Prefer in-progress files and new/changed work while reserving time for older periodic checks. Successful unchanged files become due again after 180 days. A quick probe, sampled range or old mtime is never treated as full verification.

Limits: One unprivileged worker in Bazarr; two video threads, one audio/filter thread, nice 15, requested idle I/O priority and 2 GiB decoder virtual-address-space limit. Slow ranges shrink after timeout. Scheduling priority is best-effort; this is not a container-wide CPU/RAM limit. Ten-minute settling protects recently changed files. Runtime/checkpoint limits do not guarantee timely interruption of kernel-blocked disk I/O.

Coordination: Defer or stop work when storage/array state is unavailable, Mover/parity I/O/backups are active, Bazarr is under maintenance, or Plex is transcoding. Backup locks are checked briefly; no two-hour lock delays appdata backup. Existing work is checkpointed, never used to claim an interrupted range passed. Container downtime/tool changes leave affected checks unverified.

Recovery: Disabled by default. After two distinct confirming audit runs, optional automation selects an exact profile-compliant alternative Usenet release through Sonarr v5/Radarr v3. Keep the original and its Arr file record in place; Arr handles download, import and recycling. No script-managed media move/delete, file-record deletion, monitoring/profile override, forced import or repair_hold. Existing Arr monitor provides bounded priority replacement verification between weekly scans; new grabs use the four-hour action windows. Exact-target guards prevent deletion-sync, policy cleanup or generic search from competing with recovery.

Notifications: Healthy ordinary scans are quiet. Group replacement-required findings, download starts, blocked jobs, overdue verification and verified completion into operational notifications with named media, actual actions, IDs, reasons and recent transitions. A completed replacement is explicitly reported once. Failed delivery retries; unchanged incidents remind at most weekly. No emojis.

State/logs: /mnt/vault/cloud/logs/script/media_integrity_audit. Compressed decoder state, one previous validated state, required recovery.json with original/replacement identities and up to 32 transitions per job, latest-report.txt, delivery receipt/outbox and a 1 MiB active log with two backups retained for 30 days. Missing recovery journal blocks complementary mutations; never delete it to clear a job. Existing ISS state export includes the journal.

Limits: Release metadata cannot prove healthy bytes. Completion requires exact native import/current file identity and all planned decode ranges. Native two-day bin retention proceeds independently; verification over 24 hours alerts but cannot guarantee rollback. Ambiguous/unsupported cases retain the original and require review. No app image/startup/configuration changes.

CLI: /bin/bash SCRIPT --help or --version performs no scan. --status reads the saved receipt; --recovery-status reads exact job outcomes/events. --inventory-only saves inventory without decoding. --recover-only cannot override disabled recovery. No argument runs the weekly audit. Recovery follow-up has no separate schedule.
