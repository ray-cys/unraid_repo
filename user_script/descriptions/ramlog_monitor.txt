Purpose: Monitor dedicated RAM-log storage and preserve recent application logs on vault before a clean stop or after an unexpected loss of RAM.

Schedule: Keep */10 * * * *. Each normal run checks tmpfs readiness, usage and large application directories, then checkpoints changed logs within the same invocation. No additional scheduled User Script is required. Warning/critical/recovery thresholds remain 70/90/65 percent, with the existing lifecycle notifications.

Archiving: /mnt/vault/cloud/logs/ramlog_archives contains at most two completed snapshots: the current boot's rolling checkpoint and the newest other boot. Repeated checkpoints replace only the current boot's prior snapshot, preserving the previous session for crash investigation. Each compressed payload is capped at 256 MiB (up to 512 MiB total payloads); a temporary additional archive is needed while a replacement is verified. Files with unexpected ownership markers/content are preserved for review.

The existing pre-Docker --prepare boot call also installs a RAM-resident unmounting_disks event adapter. It requests a final archive after Docker/services stop but before vault unmounting. The complete automatic attempt is limited to 25 seconds plus a two-second termination grace; failures do not prevent shutdown. The hook is recreated at each boot without editing Unraid system files or changing Docker settings.

Sudden power loss/kernel crash cannot execute a hook: use the latest completed vault checkpoint. Changes since that checkpoint can be lost; the gap may exceed ten minutes if scheduling, storage or capture fails. Snapshots of actively written logs are explicitly labelled best-effort. CRC/SHA checks verify the saved archive, not that every application flushed its internal buffers. No protection is promised against vault-device failure.

CLI: /bin/bash SCRIPT --version; --help; --install-hook (event adapter only); --archive manual (save a snapshot). Normal runs use a bounded child worker. Archive files are private and for review only. Extract into a separate directory; never replace active RAM application logs with old logs. Existing log files are never deleted, truncated or rotated by this script; only owned obsolete vault archives and interrupted staging are removed after successful verification.
