Purpose: Coordinate personal Kometa configuration checks with native MetaFusion metadata reconciliation.

Schedule: Custom 55 3,7,11,15,19,23 * * * (03:55, 07:55, 11:55, 15:55, 19:55 and 23:55, Singapore time).

Requires MetaFusion develop with native reconciliation capabilities. Kometa keeps its original image, entrypoint and internal scheduler. Honour host backup maintenance; require both applications idle and acquire the MetaFusion/wrapper writer lock. Maintain recognised personal resolution-overlay and collection-order templates. Generated metadata and deferred catalogues are owned by MetaFusion and are never rewritten by this wrapper.

Report configuration changes, failures, and successful native metadata deferral/restoration actions once per changed result. Quiet unchanged runs. Does not start Kometa, delete media or change Arr policies. Upgrade/capability failures defer edits. Native log checks and scheduling reduce overlap; stock Kometa does not participate in this lock, so exclusive consumer coordination is not guaranteed.

Weekly maintenance review (v2.2): On the first invocation after Sunday 11:55 Asia/Singapore, send one report if recorded issues or verified fixes need review. Existing cron stays unchanged. The watchdog's incremental reader supplies a bounded, redacted catalogue; this module does not scan/copy full logs again. Reporting runs before MetaFusion/Kometa idle and writer-lock checks, so an edit deferral does not suppress the read-only review.

Details include the actual error/warning, known library/YAML/source/collection context, stable issue ID, first/last observation, affected runs, occurrence count, diagnostic category, recommended action and generated-file ownership hints. Missing or shared context is explicitly unidentified; configured local files can be listed as candidates. Duplicate summary lines are suppressed. No weekly all-clear email is sent without recorded findings/fixes. Email prioritizes up to 20 items within a size cap; weekly-report.txt contains every retained item's details. Catalogue limits and partial coverage are disclosed.

A skipped or absent scope is not a verified fix. Resolution requires two completed normal runs that positively process the same scope without findings; file-loading scopes additionally require error-free run evidence. Findings not re-observed remain unverified. No extra YAML edits or automatic corrections are introduced by the reporting module. Existing personal-template reconciliation continues under its existing guards.

CLI: /bin/bash SCRIPT --report-preview prints the full current review with no email or report-state updates. --weekly-report checks the weekly deadline only and performs no YAML edits. Failed delivery keeps the deadline pending for retry. A stale/missing handoff restores immediate routine Kometa alerts through the watchdog; fatal, availability and deadline alerts always remain immediate. Review settings are configurable in the script. Current bootstrapping only sees available recent logs; it cannot reconstruct already rotated-away runs.
