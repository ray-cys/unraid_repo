# Dynamic application and User Scripts inventory

The update coordinator discovers installed Docker containers, plugins and User Scripts instead of treating its default policies as proof that an application still exists. Confirmed removals retire monitoring and update requests; stopped containers remain installed. Existing history is retained. New or reinstalled applications still follow update approval and safety policies.

The coordinator maintains the User Scripts schedule inventory. If that coordinator is removed or disabled, Docker Service Watchdog takes over schedule reconciliation. Two matching observations at least 60 seconds apart are required before removing a missing script's schedule references. A verified running job is protected until it finishes; uncertain process evidence also defers removal. Script payloads, descriptions, logs and held locks are never deleted by this reconciliation.

The persistent `/boot/config/plugins/user.scripts/schedule.json` remains authoritative. Reconciliation preserves existing settings and disabled entries, synchronizes the native RAM copy, and regenerates the User Scripts custom cron section while preserving unrelated lines. It checks for concurrent edits before atomic file publication. Native User Scripts does not share this lock, so a simultaneous UI edit causes a retry when detected; avoid editing schedules during a maintenance run. The latest pre-change JSON and cron copies are retained in `/mnt/vault/backup/script_deployments/user-scripts-schedule.previous.json`.

The coordinator's update calendar, Docker watchdog, backup health audit, restore drill vault recovery export, media health monitor and integrity audit use the same embedded inventory reader. It understands custom cron and native hourly/daily/weekly/monthly dispatchers, disabled jobs and startup/shutdown events. Renamed folders can be recognized by their script's operational identity. Backup freshness follows the actual periodic timetable, with a completion grace period and one missed occurrence allowed. Required backup jobs and the update readiness provider remain mandatory: deleting them produces an actionable protection failure rather than bypassing checks.

Restores validate the schedule against scripts inside the saved recovery snapshot, without rewriting or executing that snapshot. Recovery exports include a normalized catalog and checksums. Invalid or conflicting schedules are preserved and reported. Reconciliation results enter the existing grouped notification paths, and acknowledged events are not repeatedly reported.

The shared implementation is maintained in `tools/user_scripts_catalog.sh`; run `python3 tools/sync_user_scripts_catalog.py` after changes to refresh its seven standalone consumers. No additional runtime installation is needed on Unraid.
